# CIF-core recovery, 2026-09-10

Production `/data/shared/cssb_data/BioMol` is read-only. All database repairs and
backups are under `/data/shared/cssb_data/BioMol_clean`. Heavy work runs on SLURM
compute nodes. Completion below refers to verified outputs, not job submission.

## Execution fixes

- Execution contexts enumerate registered names, without recursively traversing
  molecular payloads or the multi-GB sequence map.
- SignalP metadata streams the sequence table once and retains relevant predictions.
  The old serialized lookup occupied 7,094,763,758 bytes. Numeric counter matching
  handles seven- versus twenty-digit ID padding; conflicting aliases fail.
- Ray installs shared metadata once per worker per run, respects allocated CPUs,
  admits work gradually using measured memory pressure, and bounds retries and
  result buffers. Python dictionaries are still deserialized per worker.
- Input sizing distributes records once. Every pipeline invocation uses unique
  shard paths and an explicit merge manifest. Successful fresh merges replace
  destinations; failures preserve preceding outputs.
- Downstream planning waits for successful upstream completion. Extraction fails
  on errors unless skipping is explicitly requested.
- The chain manifest dependency follows its actual CIF input, so chain extraction
  can start without waiting for unrelated sequence attachment. All three manifests
  have declared dependencies and pass a topological-order check.
- Chain extraction reuses one prepared model within each record rather than
  copying the full assembly for every chain. The cache is local to that record.
- CIF altloc selection groups atom IDs once rather than repeatedly scanning the
  full atom array. Tests compare the selection against the previous algorithm,
  including its existing cross-model wildcard convention.

## Correctness fixes

CCD node features and inherited bond endpoints now follow atom IDs rather than
row positions. CIF atom sets removed from newer CCD definitions use an explicitly
provided historical definition with matching IDs. Official CCD `alt_atom_id` and
`pdbx_component_atom_id` mappings are accepted only when they uniquely match the
complete CIF atom set. Ambiguous aliases or unresolved missing atoms fail instead
of silently discarding observed atoms or inventing chemistry.

The complete scan reads chemical-component tables regardless of whether they occur
before or after coordinates: 249,681 files, 1,168 candidates, no scan errors.
Earlier prefix-only scans were incomplete and are superseded. Reference matching
resolved every candidate, using 590 alias cases and 24 historical components.
`BioMol_clean/metadata/reference_ccd.lmdb` contains the selected definitions from
February 2026 and the November 9, 2024 CCD archive. Exact source selections are in
`logs/recovery/ccd_reference_report.json`; extracted official CIF blocks are under
`logs/recovery/ccd_history/`.

In 1b25 the earlier build lost four observed Mg atoms and four observed C atoms
from PTT. In 1b8j the atom-order fix changes two SO4 O4 charges. These are upstream
chemistry issues, not evidence that a training filter itself is wrong.

Equal occupancy scores previously selected chain models according to dictionary
order. Fresh selection now sorts ties deterministically. An optional reference
preserves production's choices for all 4,111,014 chain keys. Chain records also
intentionally include `release_date`.

Validation metadata retains every interaction partner and consistently uses 30%
sequence-cluster IDs. Sequences absent from the supplied clustering retain their
singleton cluster (`c` + sequence ID), matching attachment and classification;
their interaction edges are preserved so training contacts still exclude them. Connected components are computed once when excluding
clusters connected to training data.

The diagnostic build attempted all five, wrote zero, and reported five failures.
Evidence: `logs/recovery/raw_coverage.json`,
`logs/recovery/raw_exclusions_explained.json`, and per-entry tracebacks. No missing
production keys does not mean every provided raw file parsed successfully.

MSA/template bulk processing remains deferred. Some CCD/reference inputs still
resolve through existing shared paths or links; changing a single root does not
yet relocate every dependency. Preserve the CCD and chain-selection reference
LMDBs when rebuilding outputs: they are explicit reproduction inputs, not
throwaway derived caches. Historical CCD reference selection is required because
current CCD definitions alone cannot represent every provided raw CIF atom set.
