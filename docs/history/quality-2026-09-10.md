# Repository quality follow-up — September 10, 2026

This follow-up improves configuration consistency, failure reporting, and repeatable
development checks after the [CIF recovery](recovery-2026-09-10.md). It does not
replace that recovery's dataset audit or claim a fresh full rebuild.

## Changes

- All `db/` output defaults now derive from `DATA_ROOT/BioMol_clean`; an explicit
  `OUTPUT_ROOT` still takes precedence. The existing cluster default is unchanged.
- `MMCIF_ROOT` and `DISTILLATION_ROOT` relocate supplied inputs consistently across
  build configs and download helpers. The mmCIF download no longer deletes local
  files absent from the remote mirror.
- Attachment and validation consume the clusters produced by their declared DAG
  ancestors. `SEQ_CLUSTER30_PATH` and `SEQ_CLUSTER40_PATH` explicitly select provided
  cluster spaces for historical reproduction. Existing recovered DBs were not rebuilt
  with these changed defaults; retain the provided-reference overrides to reproduce
  the September 10 comparison.
- Preflight checks list/nested inputs, top-level CCD dependencies, model-choice
  references, duplicate output paths, cycles, unknown dependencies, and missing
  producer dependencies. Recipe source paths and generated outputs are excluded
  from the external-data inventory. `inspect --strict` exits nonzero on failure.
- `build-all` validates producer dependencies before submission and waits for final
  jobs to succeed. Failure in a leaf job now reaches the command's exit status.
- Historical CIF substitutions replace the compressed file actually consumed by
  ingestion. Staged writes preserve the original on invalid gzip input; bookkeeping
  retains previously applied IDs. They are no longer advertised as universally
  required preprocessing.
- Graph deduplication now counts node-label values, allowing isomorphic graphs with
  renamed nodes to share a bucket. NetworkX view access also resolves the ten type
  errors without suppressing type diagnostics.
- Pyright configuration lives in `pyproject.toml`; `dev/test.sbatch` runs the full
  suite against workspace code without importing recovery snapshots. Setup,
  provenance, and development documentation distinguish supported entry points from
  retained recovery evidence and legacy local files.

## Scope

The nine recovered CIF databases and production inputs were not rewritten during
this follow-up. A newly downloaded snapshot, an installation from an empty
environment, and bulk MSA/template workflows have not been verified here. Preflight
checks paths and dependencies, not payload validity or external tool execution.
Existing outputs are reused by presence; changing scientific input versions requires
a separate output root or an intentional rebuild.

Recovery backups, snapshots, and inherited local work are preserved. Root and
DataCooker changes remain uncommitted.
