# Manually-fixed mmCIF structures for the pdb/cif build.
#
# These PDB entries error out (or build wrongly) from the *current* wwPDB mmCIF
# snapshot, so the original BioMol build replaced each one's mmCIF with a version
# from an older, known-good snapshot BEFORE ingest (see scripts/manually_fix_cif.py
# in the legacy pipeline; source was BioMolDB_2024Oct21/cif/cif_raw). Reproducing
# production decode-identically requires the same substitution.
#
# Root cause (verified on 1ai0): these are mostly NMR ensembles whose non-polymer
# ligand/ion is re-numbered per model in atom_site (e.g. IPH at auth_seq 22 in some
# models, 31 in others) while pdbx_nonpoly_scheme records a single number, so the
# atom->scheme match by auth_seq_id fails for the divergent models. It is NOT a port
# regression (the scheme/atom logic is byte-identical to the legacy code) and NOT a
# CCD difference -- the mismatch is entirely in the mmCIF file.
#
# Apply with: structcooker fix-cif --source <corrected-cif-dir>
# See docs/manual-cif-fixes.md.
#
# Not needed with the current parser (2026-10-01; docs/manual-cif-fixes.md): the 48 that build
# match production exactly, the other 5 are absent from production too.
#
